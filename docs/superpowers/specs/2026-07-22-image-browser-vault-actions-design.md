# 图片浏览器全库操作设计

## 目标

在图片浏览器的本地模式中提供“**一键整理笔记**”和“**一键上传图床**”操作，使用户能够按现有配置批量处理整个工作空间内的本地图片，同时安全地清理因此产生的空目录。

## 范围

### 一键整理笔记

- 仅在图片浏览器的本地模式显示该按钮。
- 点击后显示二次确认对话框：
  - 标题：一键整理笔记
  - 文案：请注意！该操作会整理当前工作空间中所有的笔记本地图片。
- 确认后扫描 Vault 内全部 Markdown 笔记，调用既有 `ImageReorganizer`，并按当前整理配置执行：图片路径模板、命名模板、引用格式转换和 Wiki 引用跳过规则均保持一致。
- 整理结束后，识别因图片移动而变为空的目录，并使用 Obsidian 的回收站接口移入回收站。
- 操作结束时显示笔记数、移动数、跳过数、失败数和已清理的空目录数。

### 一键上传图床

- 仅在图片浏览器的本地模式显示该按钮。
- 在显示确认框前依次校验：
  1. 图床功能可用（`reorganizeConvertFormat` 为真）；
  2. “上传后自动替换引用”（`autoReplaceAfterUpload`）已开启；
  3. 至少存在一个启用的图床配置；
  4. Vault 内存在受支持的本地图片。
- 任一前置校验失败时给出对应提示，不显示确认框，也不开始上传。
- 点击后显示二次确认对话框：
  - 标题：一键上传图床
  - 文案：请注意！该操作会上传所有的本地图片到图床，并替换笔记为图床的链接引用。
- 确认后，沿用现有图床配置选择、上传路径模板、压缩选项与上传器实现，逐张处理本地图片：
  1. 上传图片；
  2. 仅在上传成功后，将指向该图片的笔记引用替换为图床 URL；
  3. 若“保留本地副本”（`keepLocalCopy`）关闭，将已成功上传且已完成引用替换的源图片移入回收站。
- 上传或引用回写失败的图片必须保留在本地，原有引用不应被删除。
- 完成全部上传后，只有在 `keepLocalCopy` 关闭时，清理因删除图片而为空的目录并移入回收站。
- 操作结束时显示成功、失败、保留/删除的本地图片数和已清理空目录数。

## 架构

图片浏览器 Modal 仅渲染本地模式操作入口、展示确认框并触发回调。批量编排逻辑放在插件主类或专属协调器中，复用现有 `ImageReorganizer`、`ImageScanner`、上传器工厂和引用回写功能，避免在 UI 层重复实现业务规则。

空目录清理应从受影响图片的原始父目录开始向上检查；只处理实际为空且非 Vault 根目录的目录。目录与图片一律通过 Obsidian `fileManager.trashFile` 移入回收站，不使用永久删除。

## 错误与一致性

- 所有批处理均以单个图片为故障隔离单元：单项失败不会中断其余项目。
- 上传删除流程的顺序固定为“上传成功 → 引用回写成功 → 可选移入回收站”，从而避免失效引用。
- 整理沿用 `ImageReorganizer` 的全 Vault 引用更新与并发安全策略；空目录清理只发生在整理完成后。
- 批处理期间按钮应禁用，避免重复执行同一任务。

## 测试策略

- 为全库整理入口添加测试：所有 Markdown 笔记均进入整理范围，且只清理空目录。
- 为全库上传协调逻辑添加测试：前置设置阻断、成功上传并回写、保留副本、删除副本、上传失败和回写失败时的保留行为。
- 为目录清理工具添加测试：递归清理空父目录、保留含文件或子项的目录、不处理 Vault 根目录。
- 为图片浏览器的本地模式操作入口添加 UI/行为测试，确认按钮仅在本地模式出现并正确触发确认流程。

## 非目标

- 不修改已有单图上传、已有批量上传命令或图床配置界面。
- 不新增图床服务商、网络请求协议或新的持久化设置。
- 不删除上传失败、引用回写失败或用户选择保留的本地图片。
